# Auto Update Cloud Firewall 1.1.1 — 单实例与启动显示修复

## 本版更新

- **修复：重复双击会打开多个进程。** 之前再次双击可执行文件会再起一个进程，多出一个托盘图标和一个后台任务，新窗口还常常被第一个窗口挡住。现在用命名互斥量保证只运行一份：重复启动会把已在运行的窗口提到前台，然后立刻退出。
- **修复：双击启动却直接缩进通知区域。** 开启「最小化启动」后，手动双击也会启动到托盘，看上去像没运行。这个选项现在只作用于开机自启（Run 注册表命令里带 `--minimized`），手动启动一律显示主窗口。设置页的文案也改成了「开机自启时最小化到托盘」，并注明了这一点。
- **修复：手动启动时窗口没显出来。** 启动后的几秒内会复查窗口状态，如果平台把它创建成了隐藏窗口（较慢的桌面环境、RDP 远程会话里出现过），就主动显示出来。
- **顺带：开机自启项会在每次启动时重写。** 升级换了可执行文件路径，注册表里的路径和 `--minimized` 参数都会跟着更新。

Windows 上双击即可运行，首次启动可能被 SmartScreen 拦截，选择「仍要运行」。macOS / Linux 的产物不带扩展名，下载后先 `chmod +x`，再以 `./auto-update-cloud-firewall-x86_64-linux` 这样的路径启动。Linux 更推荐取 `.tar.gz`：解压后执行权限已保留，包内同时附带 `LICENSE` 与 `README.md`。

## 升级说明

直接用新文件覆盖旧的可执行文件即可，`config.json` 向后兼容，不用改动。如果之前开着「最小化启动」而被打消了念头，可以把设置页里的「开机自启时最小化到托盘」关掉——它现在只影响开机自启。

# Auto Update Cloud Firewall 1.1.1 — single instance and a window that shows up

## What changed

- **Fixed: double-clicking spawned several processes.** Launching the executable again started a second process with its own tray icon and background worker, and the new window usually stayed behind the first one. A named mutex now keeps the app single-instance: an extra launch brings the running window to the front and exits immediately.
- **Fixed: a manual double-click could open straight into the notification area.** With "start minimized" enabled, launching the app by hand also went to the tray, so it looked like nothing had run. The option now applies to the auto-start entry only — the Run command carries `--minimized` — and a manual launch always shows the window. The setting is relabelled accordingly.
- **Fixed: the window occasionally stayed hidden on a manual launch.** For a few seconds after startup the window is re-checked and shown if the platform left it created-but-hidden (seen on slower desktops and RDP sessions).
- **Also:** the auto-start entry is rewritten on every startup, so upgrading to a new executable path keeps the registration and its `--minimized` argument correct.

## Download

| Platform | File | Status |
| --- | --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` | ✅ Verified |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin` | ⚠️ **Unverified** |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux` | ⚠️ **Unverified** |
| Linux x64 (tar.gz) | `auto-update-cloud-firewall-x86_64-linux.tar.gz` | ⚠️ **Unverified** |

Double-click on Windows; the first launch may be stopped by SmartScreen — choose to run it anyway. The macOS and Linux assets carry no extension: `chmod +x` them, then start them as `./auto-update-cloud-firewall-x86_64-linux`. On Linux the `.tar.gz` is the friendlier option — extracting it keeps the executable bit, and it bundles `LICENSE` and `README.md`.

> **The macOS and Linux binaries are unverified.** They are published with this release and built in CI from the same source, but have never been launched on a real machine: the tray icon, the OS credential store (Keychain / Secret Service), window rendering and start-with-system may all be broken. Treat them as "worth a try, not supported", and please open an issue if something fails.

## Upgrading

Replace the old executable with the new one; `config.json` stays compatible and needs no edits. If "start minimized" was why the app appeared to do nothing, turn off "start in the tray at boot" — it now only affects auto-start.

# Auto Update Cloud Firewall 1.1.1 — 単一インスタンスとウィンドウ表示の修正

## 変更内容

- **修正: ダブルクリックの重複で複数プロセスが起動していた。** 実行ファイルをもう一度起動すると 2 つ目のプロセスが立ち上がり、トレイアイコンとバックグラウンド処理が増え、新しいウィンドウは多くの場合 1 つ目の後ろに隠れていました。名前付きミューテックスで単一インスタンスにしたため、重複起動時は既存のウィンドウを前面に出してすぐ終了します。
- **修正: 手動でダブルクリックしても通知領域に隠れていた。** 「最小化して起動」が有効だと手動起動でもトレイに回り、実行していないように見えました。この設定は自動起動のみに適用され（Run のコマンドに `--minimized` が付きます）、手動起動では必ずウィンドウが表示されます。設定の文言も合わせて変更しました。
- **修正: 手動起動時にウィンドウが表示されないことがあった。** 起動後数秒間ウィンドウの状態を確認し、プラットフォームが非表示のまま作成した場合（低速なデスクトップや RDP セッション）は明示的に表示します。
- **あわせて:** 自動起動のエントリは起動のたびに書き直されるため、アップグレードで実行ファイルのパスが変わっても登録と `--minimized` 引数が正しく保たれます。

## ダウンロード

| プラットフォーム | ファイル | 状態 |
| --- | --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` | ✅ 検証済み |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin` | ⚠️ **未検証** |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux` | ⚠️ **未検証** |
| Linux x64（tar.gz） | `auto-update-cloud-firewall-x86_64-linux.tar.gz` | ⚠️ **未検証** |

Windows ではダブルクリックで起動します。初回起動は SmartScreen に止められる場合があり、そのときは「実行する」を選んでください。macOS と Linux の成果物には拡張子がありません。ダウンロード後に `chmod +x` を実行し、`./auto-update-cloud-firewall-x86_64-linux` のように起動してください。Linux では `.tar.gz` を推奨します。展開すれば実行権限が保たれ、`LICENSE` と `README.md` も同梱されています。

> **macOS と Linux のバイナリは未検証です。** このリリースに含まれ、同じソースから CI でビルドされていますが、実機で起動したことはありません。トレイアイコン、OS の資格情報ストア（Keychain / Secret Service）、ウィンドウ描画、自動起動が動作しない可能性があります。「試せますが保証はしません」として扱ってください。問題があれば issue でお知らせください。

## アップグレード

新しい実行ファイルで置き換えるだけで、`config.json` はそのまま使えます。これまで「最小化して起動」が原因で何も起動していないように見えていた場合は、設定ページの「スタートアップ時は通知領域で起動」をオフにしてください。自動起動にのみ影響します。

# Auto Update Cloud Firewall 1.1.1 — 단일 인스턴스와 창 표시 수정

## 변경 사항

- **수정: 더블 클릭을 반복하면 프로세스가 여러 개 실행되던 문제.** 실행 파일을 다시 시작하면 두 번째 프로세스가 생겨 트레이 아이콘과 백그라운드 작업이 늘어났고, 새 창은 대부분 첫 번째 창 뒤에 가려졌습니다. 이름 있는 뮤텍스로 단일 인스턴스만 실행되며, 중복 실행은 기존 창을 앞으로 가져온 뒤 즉시 종료합니다.
- **수정: 직접 더블 클릭해도 알림 영역으로 숨던 문제.** "최소화 상태로 시작"이 켜져 있으면 직접 실행해도 트레이로 가서 실행되지 않은 것처럼 보였습니다. 이 설정은 이제 자동 시작에만 적용되며(Run 명령에 `--minimized`가 붙습니다), 직접 실행하면 항상 창이 표시됩니다. 설정 문구도 함께 바꿨습니다.
- **수정: 직접 실행했는데 창이 보이지 않던 문제.** 시작 후 몇 초 동안 창 상태를 확인하고, 플랫폼이 창을 숨긴 채 만들었다면(느린 데스크톱이나 RDP 세션) 직접 표시합니다.
- **함께:** 자동 시작 항목을 시작할 때마다 다시 기록하므로, 업그레이드로 실행 파일 경로가 바뀌어도 등록과 `--minimized` 인수가 올바르게 유지됩니다.

Windows에서는 더블 클릭으로 실행합니다. 첫 실행이 SmartScreen에 의해 차단될 수 있으며 이때는 "실행"을 선택하세요. macOS와 Linux 산출물에는 확장자가 없습니다. 내려받은 뒤 `chmod +x`를 실행하고 `./auto-update-cloud-firewall-x86_64-linux`처럼 실행하세요. Linux에서는 `.tar.gz`를 권장합니다. 압축을 풀면 실행 권한이 유지되고 `LICENSE`와 `README.md`도 함께 들어 있습니다.

## 업그레이드

새 실행 파일로 덮어쓰면 되고 `config.json`은 그대로 호환됩니다. "최소화 상태로 시작" 때문에 실행되지 않은 것처럼 보였다면 설정 페이지의 "Windows 시작 시 알림 영역으로 실행"을 끄면 됩니다. 이제 자동 시작에만 영향을 줍니다.
