# Auto Update Cloud Firewall 1.1.0 — 定时表达式与多目标修复

## 本版更新

- **修复：多个目标时「编辑」按钮失效。** 之前安全组里有第二个及以后的目标时，点「编辑」没有任何反应，只有第一个能打开弹窗。根因是每一行复用了同一个元素 ID（`edit-target`、`delete-target`、`target-enabled`，账号行同样如此），gpui 只把事件挂到了第一行。现在 ID 里带上了目标/账号 ID，每行都能独立响应，账号行的删除与启停也一并修正。
- **新增：定时表达式（cron）。** 设置页在固定间隔之外新增 cron 输入框，五段式（分 时 日 月 周）：`0 */5 * * *` 每 5 分钟，`0 3 * * *` 每天 03:00，`30 2 * * 1-5` 工作日 02:30；也接受 `@hourly`、`@daily`、`@weekly`、`@monthly`、`@yearly`。留空则继续按间隔执行。
- **新增：目标级调度覆盖。** 添加或编辑目标时可以单独填写「同步间隔（秒）」或「定时表达式」，留空即继承全局设置，两者都填时以定时表达式为准。弹窗里有输入示例，并显示当前全局默认值。
- **后台任务按目标调度。** 每个目标各自计算下次执行时间，不同目标可以有不同的节奏；到期的目标才同步，手动「立即同步」仍然处理全部目标。
- **界面提示更完整。** 目标卡片直接显示该目标生效的调度，如 `每 300 秒`、`定时 0 3 * * *`，继承全局时标注「（全局）」。

Windows 上双击即可运行，首次启动可能被 SmartScreen 拦截，选择「仍要运行」。macOS / Linux 的产物不带扩展名，下载后先 `chmod +x`，再以 `./auto-update-cloud-firewall-x86_64-linux` 这样的路径启动。Linux 更推荐取 `.tar.gz`：解压后执行权限已保留，包内同时附带 `LICENSE` 与 `README.md`。

## 升级说明

直接用新文件覆盖旧的可执行文件即可，`config.json` 向后兼容：旧配置没有 cron 字段，会继续按原来的间隔执行。写错的定时表达式在保存时会被拒绝；如果手工改 `config.json` 写坏了，程序会回退到全局间隔，不会停止同步。

# Auto Update Cloud Firewall 1.1.0 — cron schedules and a multi-target fix

## What changed

- **Fixed: the Edit button did nothing past the first target.** With two or more security-group targets, only the first one opened its dialog. Every row reused the same element IDs (`edit-target`, `delete-target`, `target-enabled`, and likewise for account rows), so gpui attached the handlers to the first row only. IDs now include the target or account id, so every row responds — the account delete and enable controls are fixed too.
- **Added: cron expressions.** Besides the fixed interval, the settings page now takes a five-field expression (minute hour day month weekday): `0 */5 * * *` every five minutes, `0 3 * * *` daily at 03:00, `30 2 * * 1-5` weekdays at 02:30. `@hourly`, `@daily`, `@weekly`, `@monthly` and `@yearly` also work. Leave it empty to keep using the interval.
- **Added: per-target schedule overrides.** When adding or editing a target you can give it its own interval in seconds or its own cron expression; an empty field inherits the global setting, and the expression wins when both are filled. The dialog shows an example and the global default that is currently inherited.
- **The worker schedules per target.** Each target computes its own next run, so different targets can run at different cadences; only the targets that are due get synced, while "Sync now" still covers every target.
- **Clearer UI.** Target cards show the schedule actually in effect — `every 300s`, `cron 0 3 * * *` — marked as global when inherited.

## Download

| Platform | File | Status |
| --- | --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` | ✅ Verified |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin` | ⚠️ **Unverified** |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux` | ⚠️ **Unverified** |
| Linux x64 (tar.gz) | `auto-update-cloud-firewall-x86_64-linux.tar.gz` | ⚠️ **Unverified** |

Double-click on Windows; the first launch may be stopped by SmartScreen — choose to run it anyway. The macOS and Linux assets carry no extension: `chmod +x` them, then start them as `./auto-update-cloud-firewall-x86_64-linux`. On Linux the `.tar.gz` is the friendlier option — extracting it keeps the executable bit, and it bundles `LICENSE` and `README.md`.

> **The macOS and Linux binaries are unverified.** They are published with this release and built in CI from the same source, but have never been launched on a real machine: the tray icon, the OS credential store (Keychain / Secret Service), window rendering and start-with-system may all be broken. Treat them as "worth a try, not supported", and please open an issue if something fails.

## Upgrading

Replace the old executable with the new one; `config.json` stays compatible. Older configs have no cron field and keep running on their interval. An invalid expression is rejected when saving; if a hand-edited `config.json` breaks one, the app falls back to the global interval instead of stopping.

# Auto Update Cloud Firewall 1.1.0 — cron 式と複数ターゲットの修正

## 変更内容

- **修正: 2 つ目以降のターゲットで「編集」が効かない。** セキュリティグループのターゲットが複数あるとき、最初の 1 つしかダイアログが開きませんでした。各行が同じ要素 ID（`edit-target`、`delete-target`、`target-enabled`、アカウント行も同様）を再利用していたため、gpui が最初の行にしかハンドラーを登録していなかったのが原因です。ID にターゲット ID・アカウント ID を含めたので、どの行も正しく反応します（アカウントの削除・有効化も同様に修正）。
- **追加: cron 式。** 設定ページで固定間隔に加えて 5 フィールド形式（分 時 日 月 曜日）を指定できます。`0 */5 * * *` は 5 分ごと、`0 3 * * *` は毎日 03:00、`30 2 * * 1-5` は平日 02:30。`@hourly`・`@daily`・`@weekly`・`@monthly`・`@yearly` も使えます。空欄なら従来どおり間隔で実行します。
- **追加: ターゲット単位のスケジュール。** 追加・編集時に「同期間隔（秒）」または「cron 式」を個別に指定できます。空欄ならグローバル設定を継承し、両方を入力した場合は cron 式を優先します。ダイアログには入力例と、現在継承しているグローバル既定値を表示します。
- **ワーカーはターゲットごとにスケジュール。** 各ターゲットが次回実行時刻を計算するため、ターゲットごとに異なるペースで動かせます。期限が来たターゲットだけを同期し、「今すぐ同期」は全ターゲットを処理します。
- **表示の改善。** ターゲットカードに実際に適用されるスケジュール（`300 秒ごと`、`cron 0 3 * * *`）を表示し、継承している場合は「グローバル」と明記します。

# Auto Update Cloud Firewall 1.1.0 — cron 식과 다중 대상 수정

## 변경 사항

- **수정: 두 번째 이후 대상에서 "편집"이 동작하지 않던 문제.** 보안 그룹 대상이 여러 개일 때 첫 번째 대상만 대화상자가 열렸습니다. 각 행이 같은 요소 ID(`edit-target`, `delete-target`, `target-enabled`, 계정 행도 동일)를 재사용해서 gpui가 첫 행에만 핸들러를 등록한 것이 원인이었습니다. 이제 ID에 대상 ID와 계정 ID가 포함되어 모든 행이 정상 동작하며, 계정 삭제·사용 설정도 함께 수정되었습니다.
- **추가: cron 식.** 설정 페이지에서 고정 간격 외에 5개 필드 형식(분 시 일 월 요일)을 지정할 수 있습니다. `0 */5 * * *`는 5분마다, `0 3 * * *`는 매일 03:00, `30 2 * * 1-5`는 평일 02:30. `@hourly`, `@daily`, `@weekly`, `@monthly`, `@yearly`도 됩니다. 비워 두면 기존처럼 간격으로 실행합니다.
- **추가: 대상별 스케줄.** 추가·편집할 때 "동기화 간격(초)" 또는 "cron 식"을 따로 지정할 수 있습니다. 비워 두면 전역 설정을 따르고, 둘 다 입력하면 cron 식을 우선합니다. 대화상자에 입력 예시와 현재 상속 중인 전역 기본값을 표시합니다.
- **작업자가 대상별로 스케줄링.** 각 대상이 다음 실행 시각을 계산하므로 대상마다 다른 주기로 실행할 수 있습니다. 만기가 된 대상만 동기화하고, "지금 동기화"는 모든 대상을 처리합니다.
- **화면 표시 개선.** 대상 카드에 실제 적용되는 스케줄(`300초마다`, `cron 0 3 * * *`)을 표시하고, 전역에서 상속한 경우 "(전역)"이라고 표시합니다.

## 업그레이드

새 실행 파일로 덮어쓰면 되고 `config.json`은 그대로 호환됩니다. 이전 설정에는 cron 항목이 없어 기존 간격으로 계속 실행됩니다. 잘못된 식은 저장할 때 거부되며, `config.json`을 직접 고쳐 망가뜨려도 동기화를 멈추지 않고 전역 간격으로 돌아갑니다.
