# Auto Update Cloud Firewall 1.0.0 — 首个稳定版本

让云安全组的入站白名单始终指向你当前的公网 IPv4：常驻通知区域、按间隔检测、只改动它自己管理的规则。

## 主要能力

- **多账号、多安全组** —— 阿里云 ECS 与腾讯云 CVM 可混用，每个账号持有独立的 AccessKey 与地域，一个账号下可挂多个安全组目标。
- **一个目标多条规则** —— 每条规则 = 协议 + 端口或范围（`5432`、`8000-8010`、`8000/8010`）+ 可选的备注关键字。
- **按备注关键字就地改 IP** —— 命中即替换源地址，备注与优先级原样保留，不会多出一条重复规则；同一关键字命中多条时整个目标报错跳过，绝不猜。
- **只动自己的规则** —— 没填关键字的规则按描述前缀（默认 `AutoFirewall`）归属，手动创建的规则永远不会被修改或删除。
- **演练模式** —— 只把计划写进日志，不调用任何写接口。
- **后台常驻** —— 关窗即缩到托盘，后台继续同步；支持开机自启与最小化启动（Windows）。
- **活动日志** —— 界面保留最近 500 条，完整日志追加写入 `%LOCALAPPDATA%\AutoUpdateCloudFirewall\logs\app.log`。
- **四种界面语言** —— 英语、简体中文、日语、韩语，切换即时生效（界面、对话框、托盘菜单与新增日志）。
- **密钥不落盘** —— AccessKey 密钥存入系统凭据存储，`config.json` 里只有 AccessKey ID。

## 下载

| 平台 | 文件 |
| --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin.exe` |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux.exe` |

Windows 上双击即可运行。macOS / Linux 上下载后先 `chmod +x` 再执行。首次运行可能被 SmartScreen 或 Gatekeeper 拦截，选择"仍要运行"。

> 1.0.0 的完整测试覆盖仅限 Windows。macOS 与 Linux 使用同一份代码构建，托盘与开机自启等系统集成在这些平台上未做同等验证。

## 首次使用

1. 打开 **云账号**，添加一个 AccessKey（建议使用专用的 RAM / CAM 子用户）。
2. 打开 **安全组**，添加目标：安全组 ID、地域（可选，默认跟随账号）、以及若干规则行。
3. 打开 **设置 → 演练模式**，点 **立即同步** 跑一轮，确认活动日志里的计划符合预期。
4. 关闭演练模式，正式同步。

## 云 API 权限

未使用任何云厂商 SDK，两套请求签名均为直接实现。

**阿里云 RAM** —— `ecs:DescribeSecurityGroups`、`ecs:DescribeSecurityGroupAttribute`、`ecs:AuthorizeSecurityGroup`、`ecs:RevokeSecurityGroup`、`ecs:ModifySecurityGroupRule`

**腾讯云 CAM** —— `DescribeSecurityGroups`、`DescribeSecurityGroupPolicies`、`CreateSecurityGroupPolicies`、`DeleteSecurityGroupPolicies`

## 已知限制

- 仅处理 **IPv4** 与 **入站** 规则。
- 腾讯云没有单条规则修改接口，改源 IP 等同「按原备注删除 + 重建」，规则 ID 会变，备注与优先级保留。
- 只能把源 IP 改成**当前公网 IP**，无法回填 `0.0.0.0/0` 这类放宽地址，需要时请到控制台手工修改。
- 同一关键字命中多条规则时不会自动挑选，整个目标跳过并报错。

## 隐私

无遥测、无自动更新检查。除了你配置的 IP 查询服务与两家云厂商的 API 端点，程序不发起其他网络请求。

# Auto Update Cloud Firewall 1.0.0 — first stable release

Keeps a cloud security group's ingress allow-list pointed at your current public IPv4: it lives in the tray, re-checks on an interval, and only touches the rules it owns.

## What it does

- **Several accounts, several groups** — Aliyun ECS and Tencent Cloud CVM side by side; each account keeps its own AccessKey and region and can drive multiple security-group targets.
- **Several rules per target** — one row is protocol + a port or range (`5432`, `8000-8010`, `8000/8010`) + an optional description keyword.
- **In-place updates by description keyword** — the matching rule keeps its description and priority and only its source address is rewritten, so no duplicate rule appears. If a keyword matches more than one rule the whole target is skipped with an error instead of guessing.
- **Only its own rules** — rows without a keyword are owned by the description prefix (default `AutoFirewall`); rules you created by hand are never modified or deleted.
- **Dry-run mode** — logs the plan without calling any write API.
- **Background operation** — closing the window hides it to the tray and keeps the worker running; start with the system or minimized (Windows).
- **Activity log** — the newest 500 entries in the UI, the full stream appended to `%LOCALAPPDATA%\AutoUpdateCloudFirewall\logs\app.log`.
- **Four UI languages** — English, Simplified Chinese, Japanese and Korean, switching instantly across the window, dialogs, tray menu and new log lines.
- **Secrets stay out of the config** — AccessKey secrets go to the OS credential store; `config.json` only holds the AccessKey ID.

## Download

| Platform | File |
| --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin.exe` |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux.exe` |

Double-click on Windows. On macOS and Linux, `chmod +x` the file first. The first launch may be stopped by SmartScreen or Gatekeeper — choose to run it anyway.

> The 1.0.0 test pass covers Windows only. The macOS and Linux binaries are built from the same source, but tray and auto-start integration are not verified to the same degree there.

## Getting started

1. In **Cloud accounts**, add an AccessKey (a dedicated RAM / CAM sub-user is recommended).
2. In **Security groups**, add a target: group ID, optional region override, and its rule rows.
3. Turn on **Settings → Dry run**, press **Sync now** once and check the plan in the activity log.
4. Turn dry run off and sync for real.

## Cloud API permissions

No vendor SDK is used; both request signatures are implemented directly.

**Aliyun RAM** — `ecs:DescribeSecurityGroups`, `ecs:DescribeSecurityGroupAttribute`, `ecs:AuthorizeSecurityGroup`, `ecs:RevokeSecurityGroup`, `ecs:ModifySecurityGroupRule`

**Tencent Cloud CAM** — `DescribeSecurityGroups`, `DescribeSecurityGroupPolicies`, `CreateSecurityGroupPolicies`, `DeleteSecurityGroupPolicies`

## Known limitations

- IPv4 and **ingress** rules only.
- Tencent Cloud has no per-rule update call, so changing an address revokes and re-creates the rule: the rule ID changes, description and priority are kept.
- Only the current public address can be written; widening a rule back to `0.0.0.0/0` has to be done in the cloud console.
- A keyword that matches several rules is never resolved automatically — the target is skipped with an error.

## Privacy

No telemetry, no update check. Apart from the IP lookup services you configure and the two cloud API endpoints, the app makes no network requests.

# Auto Update Cloud Firewall 1.0.0 — 最初の安定版

クラウドのセキュリティグループのインバウンド許可リストを、常に現在のパブリック IPv4 に向けておくためのツールです。通知領域に常駐し、一定間隔で再確認し、自分が管理するルールだけを書き換えます。

## 主な機能

- **複数アカウント・複数グループ** — Aliyun ECS と Tencent Cloud CVM を併用でき、アカウントごとに AccessKey とリージョンを保持します。1 つのアカウントに複数のセキュリティグループ対象を割り当てられます。
- **1 つの対象に複数のルール** — 1 行 = プロトコル + ポートまたは範囲（`5432`、`8000-8010`、`8000/8010`）+ 任意の説明キーワード。
- **説明キーワードによるその場での IP 更新** — 一致したルールは説明と優先度を保ったまま送信元アドレスだけが置き換わり、重複ルールは作られません。キーワードが複数のルールに一致した場合は推測せず、対象全体をエラーでスキップします。
- **自分のルールだけを変更** — キーワードのない行は説明のプレフィックス（既定 `AutoFirewall`）で管理され、手動で作成したルールは決して変更・削除されません。
- **ドライラン** — 計画をログに書くだけで、書き込み API は呼びません。
- **バックグラウンド動作** — ウィンドウを閉じると通知領域に隠れ、ワーカーは動き続けます。Windows では自動起動と最小化起動に対応。
- **アクティビティログ** — UI に最新 500 件、全量は `%LOCALAPPDATA%\AutoUpdateCloudFirewall\logs\app.log` に追記されます。
- **4 言語の UI** — 英語・簡体中国語・日本語・韓国語。ウィンドウ、ダイアログ、トレイメニュー、新しいログ行に即時反映されます。
- **秘密情報を設定ファイルに残さない** — AccessKey のシークレットは OS の資格情報ストアに保存し、`config.json` には AccessKey ID だけを書きます。

## ダウンロード

| プラットフォーム | ファイル |
| --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin.exe` |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux.exe` |

Windows ではダブルクリックで起動します。macOS と Linux ではダウンロード後に `chmod +x` を実行してください。初回起動は SmartScreen や Gatekeeper に止められる場合があります。その場合は「実行する」を選んでください。

> 1.0.0 のテストは Windows のみで実施しています。macOS と Linux は同じソースからビルドしていますが、トレイや自動起動などの OS 連携は同等には検証していません。

## はじめかた

1. **クラウドアカウント** で AccessKey を追加します（専用の RAM / CAM サブユーザーを推奨）。
2. **セキュリティグループ** で対象を追加します。グループ ID、任意のリージョン上書き、ルール行を指定します。
3. **設定 → ドライラン** を有効にし、**今すぐ同期** を 1 回実行して、アクティビティログの計画を確認します。
4. ドライランを切り、本番の同期を行います。

## クラウド API の権限

ベンダー SDK は使用しておらず、2 種類のリクエスト署名はどちらも直接実装しています。

**Aliyun RAM** — `ecs:DescribeSecurityGroups`、`ecs:DescribeSecurityGroupAttribute`、`ecs:AuthorizeSecurityGroup`、`ecs:RevokeSecurityGroup`、`ecs:ModifySecurityGroupRule`

**Tencent Cloud CAM** — `DescribeSecurityGroups`、`DescribeSecurityGroupPolicies`、`CreateSecurityGroupPolicies`、`DeleteSecurityGroupPolicies`

## 既知の制限

- **IPv4** と **インバウンド** ルールのみを扱います。
- Tencent Cloud にはルール単位の更新 API がないため、送信元 IP の変更は「元の説明で削除して再作成」になります。ルール ID は変わりますが、説明と優先度は保持されます。
- 書き込めるのは**現在のパブリック IP** のみです。`0.0.0.0/0` のような広い範囲に戻す場合は、コンソールで手動で変更してください。
- 同じキーワードが複数のルールに一致した場合、自動では選択せず、対象全体をスキップしてエラーにします。

## プライバシー

テレメトリーも更新確認もありません。設定した IP 検索サービスと 2 社のクラウド API 以外に、ネットワーク要求は行いません。

# Auto Update Cloud Firewall 1.0.0 — 첫 안정 버전

클라우드 보안 그룹의 인바운드 허용 목록을 항상 현재 공인 IPv4 주소로 유지합니다. 알림 영역에 상주하며 일정 간격으로 다시 확인하고, 자신이 관리하는 규칙만 수정합니다.

## 주요 기능

- **여러 계정, 여러 보안 그룹** — Aliyun ECS와 Tencent Cloud CVM을 함께 사용할 수 있고, 계정마다 AccessKey와 리전을 따로 보관합니다. 한 계정에 여러 보안 그룹 대상을 연결할 수 있습니다.
- **대상 하나에 여러 규칙** — 한 줄은 프로토콜 + 포트 또는 범위(`5432`, `8000-8010`, `8000/8010`) + 선택적 설명 키워드로 구성됩니다.
- **설명 키워드로 원본 IP를 그 자리에서 교체** — 일치한 규칙은 설명과 우선순위를 그대로 유지한 채 원본 주소만 바뀌며, 중복 규칙이 생기지 않습니다. 키워드가 여러 규칙과 일치하면 추측하지 않고 대상 전체를 오류로 건너뜁니다.
- **자신의 규칙만 변경** — 키워드가 없는 줄은 설명 접두사(기본값 `AutoFirewall`)로 관리되며, 직접 만든 규칙은 절대 수정하거나 삭제하지 않습니다.
- **드라이런** — 계획만 로그에 기록하고 쓰기 API는 호출하지 않습니다.
- **백그라운드 실행** — 창을 닫으면 알림 영역으로 숨겨지고 작업은 계속 실행됩니다. Windows에서는 자동 시작과 최소화 시작을 지원합니다.
- **활동 로그** — UI에는 최근 500건, 전체 기록은 `%LOCALAPPDATA%\AutoUpdateCloudFirewall\logs\app.log`에 추가됩니다.
- **4개 언어 UI** — 영어, 중국어(간체), 일본어, 한국어. 창, 대화 상자, 트레이 메뉴, 새 로그 줄에 즉시 반영됩니다.
- **비밀 정보는 설정 파일에 남기지 않음** — AccessKey 시크릿은 OS 자격 증명 저장소에 보관하고, `config.json`에는 AccessKey ID만 기록합니다.

## 다운로드

| 플랫폼 | 파일 |
| --- | --- |
| Windows 10/11 x64 | `auto-update-cloud-firewall-x86_64-windows.exe` |
| macOS x64 | `auto-update-cloud-firewall-x86_64-darwin.exe` |
| Linux x64 | `auto-update-cloud-firewall-x86_64-linux.exe` |

Windows에서는 더블 클릭으로 실행합니다. macOS와 Linux에서는 먼저 `chmod +x`를 실행하세요. 첫 실행이 SmartScreen이나 Gatekeeper에 의해 차단될 수 있으며, 이때는 "실행"을 선택하면 됩니다.

> 1.0.0 테스트는 Windows에서만 수행했습니다. macOS와 Linux는 같은 소스로 빌드했지만, 트레이와 자동 시작 같은 OS 연동은 동일한 수준으로 검증하지 않았습니다.

## 시작하기

1. **클라우드 계정**에서 AccessKey를 추가합니다(전용 RAM/CAM 하위 사용자를 권장).
2. **보안 그룹**에서 대상을 추가합니다. 그룹 ID, 선택적 리전 재정의, 규칙 줄을 지정합니다.
3. **설정 → 드라이런**을 켜고 **지금 동기화**를 한 번 실행해 활동 로그의 계획을 확인합니다.
4. 드라이런을 끄고 실제로 동기화합니다.

## 클라우드 API 권한

벤더 SDK를 사용하지 않으며, 두 가지 요청 서명을 모두 직접 구현했습니다.

**Aliyun RAM** — `ecs:DescribeSecurityGroups`, `ecs:DescribeSecurityGroupAttribute`, `ecs:AuthorizeSecurityGroup`, `ecs:RevokeSecurityGroup`, `ecs:ModifySecurityGroupRule`

**Tencent Cloud CAM** — `DescribeSecurityGroups`, `DescribeSecurityGroupPolicies`, `CreateSecurityGroupPolicies`, `DeleteSecurityGroupPolicies`

## 알려진 제한

- **IPv4**와 **인바운드** 규칙만 처리합니다.
- Tencent Cloud에는 규칙 단위 수정 API가 없어 원본 IP 변경은 "원래 설명으로 삭제 후 재생성"이 됩니다. 규칙 ID는 바뀌지만 설명과 우선순위는 유지됩니다.
- 기록할 수 있는 주소는 **현재 공인 IP**뿐입니다. `0.0.0.0/0`처럼 넓은 범위로 되돌리려면 콘솔에서 직접 수정해야 합니다.
- 같은 키워드가 여러 규칙과 일치하면 자동으로 고르지 않고 대상 전체를 오류로 건너뜁니다.

## 개인정보

텔레메트리도, 자동 업데이트 확인도 없습니다. 설정한 IP 조회 서비스와 두 클라우드 API 엔드포인트 외에는 네트워크 요청을 보내지 않습니다.
